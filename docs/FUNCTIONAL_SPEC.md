# Camp Room 기능명세서

Camp Room은 Pleos 차량 화면에서 **찾기 → 내 캠핑 → 단계별 준비 → 차박 → 다음 여행**을 연결한다. 앱은 Kotlin·Jetpack Compose, 서버는 FastAPI와 Turso·SQLite로 구성한다. API 형식은 [OpenAPI 계약](../apps/api/openapi.json)을 따른다.

## 주요 화면

| 화면 | 제공하는 경험 |
| --- | --- |
| 찾기 | 지역·날짜·인원·시설 조건 검색, 주변 장소 정렬, 목록·사진·상세 확인 |
| 내 캠핑 | 장소·일정·인원 저장, 시간별 예보, 경로 미리보기, 준비물·식사 선택 |
| 차박 | 배터리·온도·기능별 영역 관측, 취침·출발 장면 미리보기, 같은 여행의 준비 이어가기 |

### 찾기

여행 날짜·인원과 지역·차박·시설 조건으로 캠핑장을 탐색한다. 필터는 함께 적용되며 결과 수·페이지 이동·조건 초기화를 제공한다. 카드에는 장소명·지역·사진·시설·출처·갱신 시각을 보여 준다.

상세에서 설명·이용 수칙·입퇴실·전기·EV 충전·배송 수령 조건을 살펴보고 `내 캠핑에 담기`로 장소와 일정을 저장한다. 가용성은 선택한 숙박 기간·인원·사이트 조건에 맞춰 표시한다.

### 내 캠핑

저장한 장소·일정·인원과 시간별 예보·밤사이 기온·비 가능성을 보여 준다. 외부 예보와 차량의 실내 측정값을 각각 표시한다. 경로 미리보기에는 거리·예상 에너지·도착 SOC와 제공되는 경로 정보를 출처에 맞춰 표시한다.

사진·구성·인분 안내로 식사를 고르고 챙길 물품을 선택한다. 준비 카드에서 단계별 확인을 이어가고, 여행을 저장하기 전에는 찾기로 연결한다.

## 도착·체류·출발 준비

사용자가 `도착했을 때 / 머무는 동안 / 돌아가기 전`을 선택하고 살펴본 항목을 직접 체크한다.

| 단계 | 준비 항목 |
| --- | --- |
| 도착 | 이용 수칙·전원 계획·인원에 맞는 준비물 |
| 체류 | 실내·주변 환경·전원 사용·식사와 보관 |
| 출발 | 케이블·짐·문·창문·주변 정리 |

차량 안내에는 값·출처·원본 표본 시각·상태를 함께 표시하고 관련 수동 항목을 강조한다. 배터리 표본은 60초, 문·창문 위치 표본은 15초 기준으로 최신성을 살핀다. 최근 SOC가 30% 미만이면 충전 계획을 먼저 안내한다.

관측 시각과 상태에 맞춰 직접 확인할 행동을 보여 준다. 반복 조회에서는 원본 표본 시각과 사용자의 체크를 유지하고, 새로운 차량 연결·관측 조건에서는 관련 항목을 다시 살펴보도록 안내한다. 완료 체크는 사용자가 직접 수행한다.

## 저장과 다음 여행

여행 장소·입퇴실 날짜별로 준비 단계·체크·물품·식사 선택을 기기에 보관한다. 메뉴를 이동하거나 다시 열어도 같은 여행의 준비를 이어간다.

다음 여행 목록에는 선택한 물품과 식사를 보관한다. 다른 여행에서 가져오면 도착 단계와 빈 완료 체크로 시작하고, 차량 관측·확인 시각은 새 여행에서 구성한다. 인원에 맞춰 식사·짐을 다시 살펴볼 수 있다.

사용 기록은 동의한 뒤의 체크·단계 변경·가져오기 횟수를 기기에 집계한다. 사용자가 기록을 끄면 집계를 초기화한다.

## 차박·위치·음성

차박은 배터리·측정 온도·원본 기능 영역·관측 시각과 연결 출처를 보여 준다. 짐 정리·함께 쉬기·독서와 휴식·취침·출발 장면을 미리 보고 준비 안내로 연결한다. 차량 요청은 기능별 지원 범위·권한·호스트의 주차 확인 조건에 따라 처리하고 요청 목표와 관측값을 각각 표시한다.

내 주변은 최근 관측 위치를 기준으로 현재 목록을 정렬한다. 캠핑장 500m 진입·이탈 알림은 등록과 감지 상태로 구분한다. 여행 안내는 선택한 한국어·영어로 제공하며 음성·직접 입력은 명령 미리보기로 이어진다. 실행은 해당 화면에서 사용자가 확인한다.

Pleos 빌드는 차량 내 SDK, demo 빌드는 개발용 차량·내비 시뮬레이터를 사용한다. SDK 버전과 역할은 [SDK 적용표](product/SDK_CAPABILITY_MATRIX.md)에 정리했다.

## 서버와 운영

캠핑장·사진·예보는 공급자 API로 조회하며 출처·상태·갱신 시각을 보존한다. 서버 설정의 `demo`는 개발 데이터, `live`는 실제 공급자, `auto`는 공급자 상태에 따른 개발 연결 모드다.

Turso와 SQLite는 같은 32개 관계형 테이블을 사용한다. 캠핑장·시설·현재 여행·예보·데모 주문을 저장하고 준비 체크와 다음 여행 목록은 앱 로컬에 보관한다. 저장 관계는 [ERD](database/ERD.md)를 따른다.

관리자 웹은 로그인 후 공급자·DB 상태, 캠핑장 수령 조건과 데모 주문·운영 메모를 관리한다. worker는 공유 캠핑장·날씨 캐시를 갱신하고 최근 게시된 데이터를 제공한다. 실행 구성은 [서버 구조도](architecture/SERVER_ARCHITECTURE.md), 인증 설정은 [인증 안내](AUTH.ko.md)에 연결한다.

개발용 상거래 흐름은 상품 담기·수량·총액·배송지 견적·데모 주문으로 구성한다. 서버는 가격·재고·수령 조건·체류 날짜를 확인하고 같은 요청 키의 주문을 일관되게 처리한다.

## 화면과 검증 과업

한국어·영어와 주간·야간 테마, Asta Sans, 큰 글씨·좁은 화면 배치를 지원한다. 날짜·금액·음성 언어에 선택 언어를 반영한다. 버튼은 눌림·처리 중 상태와 햅틱을 제공하며 차량의 사용 제한 상태에 맞춰 화면과 동작을 구성한다.

핵심 확인 과업은 조건 검색·상세, 여행 저장·복원, 단계별 직접 체크, 식사·준비물 선택, 다음 여행 가져오기, 관측값·출처·시각 표시, 차박과 내 캠핑의 왕복이다. 데모 주문은 수량·배송 조건·중복 요청·저장 결과를 확인한다.

실행 방법·데모 영상·서버 구성은 [README](../README.md), 제출 파일은 [APK 안내](../apk/README.md)를 참고한다.
