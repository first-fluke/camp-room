# Camp Room 제출 설명 초안

작성일: 2026-10-28, 검증 현황 갱신: 2026-10-29 UTC. 이 문서는 저장소 내부 제출 준비 자료이며 외부 신청서를 제출하지 않았다. 구현, 실행 근거, 제안과 미검증 항목을 구분한다. 자체 검수 기준은 공식 심사 점수나 수상을 보장하지 않는다.

## 제안하는 경험

Camp Room은 차량의 큰 화면에서 캠핑장을 찾고, 같은 여행에 장소·일정·준비물을 모아 두며, 머무는 동안 필요한 차량 관측값을 함께 살펴보는 앱이다. 찾기·내 캠핑·차박의 세 메뉴와 사진이 있는 바비큐 준비 목록을 제공한다.

차별화 가설은 **동일 여행 계획의 도착–체류–철수와 차량 실측값을 연결해 다음 준비를 바꾸는 경험**이다. 현재는 장소 저장, 여행 정보, 준비 목록과 차량 상태 화면을 제공한다. 체류·철수의 맥락별 안내와 다음 여행 준비에 반영하는 폐쇄 고리는 후속 검증 과제이며 완료된 자동화로 주장하지 않는다. 최초의 캠핑 모드나 차량 상태 앱이라고 주장하지 않는다.

## 구현과 증거의 경계

| 영역 | 확보한 구현·기존 근거 | 완료로 주장하지 않는 항목 |
| --- | --- | --- |
| 캠핑장 탐색 | 고캠핑 정보·사진 표시, 필터, 서버 카탈로그와 앱 페이지 전환, 상세 보기, 날짜 선택 | 예약 가능 재고 조회, 실제 예약·결제 |
| 날씨·여행 | 기상청 예보 연결, 저장한 여행과 장소·일정 표시 | 모든 지역·날짜의 무제한 예보 보장 |
| 차량 관측 | Pleos 전용 빌드, 공식 Pleos 에뮬레이터의 기존 배터리·온도·위치 및 일부 경로 미리보기 근거 | 실차 검증, 전체 SDK 성공, 안내 시작 성공, 최신 빌드의 모든 음성 기능 |

| 문·창문 후속 수정 | 영역별 capability/getter/listener, 조회 취소·리스너 보존·유한 재시도 방어. 최신 244개 테스트와 APK/설치 해시, 동일 ViewModel 재개 및 별도 전체 해제 기록 연결 | 실차 위치 변경·닫힘 판정, 실제 영구 해제 실패 및 희귀 active_reuse 경합의 실기 재현 |

문·창문의 수치 의미가 공식적으로 확인되지 않으면 raw 관측만 유지한다. 최솟값 또는 0을 일괄적으로 닫힘으로 해석하지 않으며, 잠금을 닫힘으로 대신하지 않는다. 미지원·권한·시간초과·오래된 관측을 정상 상태로 바꾸지 않는다.

신뢰할 수 있는 PARKED 신호의 연결을 확인하지 못했으므로 제어 차단을 유지한다. 2026-10-28 14:00 UTC의 소스 확인에서 [PleosSdkModule.kt의 `motion()` 공급자](../../apps/pleos/app/src/pleos/java/camp/room/app/di/PleosSdkModule.kt#L26)는 `MotionProvider { MotionState.UNKNOWN }`을 반환한다. 이는 현재 DI 구성의 정적 근거이며 실제 주차 감지 성공의 근거가 아니다. UX 제한 해제, 브레이크, 목표 속도, geofence 진입을 주차로 간주하지 않는다. 이 후속 작업은 읽기 관측이며 물리 차량 제어는 검증 범위가 아니다.

## 다음 완료 기록의 형식

최종 검증자는 수정 소스 SHA-256, 테스트 XML의 시각·개수·실패 수, APK SHA-256, 설치된 APK SHA-256, 에뮬레이터 이미지/기기 식별과 시각을 하나의 기록으로 연결한다. 영역별 capability와 접근 수준, getter 결과, 실제 이벤트 수신 여부, 동일 listener 해제, 재연결 후 오래된 응답 폐기를 각각 기록한다. 등록 함수의 정상 반환을 이벤트 수신 성공으로 대신하지 않는다. 관측되지 않은 이벤트나 외부 서비스 제약은 미검증으로 남긴다.

## 역사적 검증: 2026-10-28 초기 후속 패치

취소·UX Binder·이벤트 순서 수정 후 앱 단위 테스트 141개가 실패·오류 없이 통과했다. Pleos debug APK SHA-256 `8a175bfe5fb0aaacaf0faab3342cabd753fb58b11d99305b483a95e19e0b574f`와 설치본이 일치한다. 공식 AVD/VehicleService 2.3.22에서 문 6개·창문 4개 영역의 capability, 등록 10건, 실제 구독 이벤트 18건, accepted getter 67건을 기록했다. 읽기 호출 134건은 모두 메인 스레드 밖에서 실행됐다. raw 값 0은 닫힘 판정이나 실제 위치 변경 시험의 근거가 아니다.

당시 해제·재연결은 미완료였다. 정상 읽기가 확보된 VM이 종료됐고, 복구 VM의 capability 조회가 시간초과했다. 당시 position.unregister 0건을 Car UX 해제 1건으로 대체하지 않는다. 이 초기 빌드의 원시 자료는 로컬에 보존하며 아래 최신 빌드의 관측 결과와 구분한다.

## 최신 검증: 2026-10-28 23:49 UTC

앱 테스트 244개가 실패·오류·건너뜀 없이 통과했고, 관련 소스 44개와 XML 29개의 해시를 연결했다. PleosDebug APK와 설치본의 SHA-256은 모두 `26f7611cf918756b08db550f1dce898a60fb82435956ec8aa898100f8df104f5`다. debug 서명이며 제출용 release가 아니다.

공식 Pleos AVD에서 동일한 ViewModel·adapter·assistant의 STOP(epoch 2)→START(epoch 3)를 확인했다. 문·창문 리스너 해제·재등록 각 10건, CarUx 해제·disconnect·등록 각 1건, Fused 해제·재등록 각 1건이 Main 밖에서 실행됐다. 새 SOC 구독 100이 늦은 getter보다 우선했다. 별도의 Activity 재생성에서는 이전 Vehicle/Fused의 전체 release와 새 owner의 등록을 확인했다. 두 수명주기 시험은 서로 대신하는 근거가 아니다.

자동 정리 알림은 재시도 예산을 초기화하지 않고, 확인된 사용자 요청만 제한된 재시도를 재개한다. 기존 15초 backoff와 자동 한도 정지·명시적 복구는 모의 시계/엔진 회귀로 검증했다. 실제 영구 해제 실패와 희귀 active_reuse 경합은 AVD에서 유도하지 않았다. SmartGlass 60001, 목표 온도 오류와 초기 SOC capability timeout은 원시 기록에 남아 있다. 실제 음성 장치와 안내 시작은 이번 검증에서 실행하지 않았다.

[최신 검증 요약](../verification/SDK_VALIDATION_SUMMARY_20261029.md)과 [시점별 검증 기록](../verification/SDK_RETRY_BUDGET_20261028_2305.json)에 범위·해시·한계를 연결한다. 기록의 review-runtime 경로는 로컬 보존 자료이며 원격 저장소에 원시 로그·APK·SDK 이미지·캐시를 포함했다는 뜻이 아니다. 이 결과로 전체 SDK 성공이나 네 항목 5/5를 선언하지 않는다.
