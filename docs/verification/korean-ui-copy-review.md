# 캠프룸 UI 문구·레이아웃 변경 검토

## 개요

최신 APK 소스는 `49c7fe685c8d08c1379856890bc1913df0725032`이다. 기존 UI 수정에 내 캠핑 그림 영역의 `clipToBounds`와 하단 앱 이름 수정을 추가했다. 한국어 화면 상단·하단에 사용할 앱 이름을 ‘캠프룸’으로 지정하고 데이터 제공사의 고유명은 유지했다.

같은 의미를 반복하던 영문 장식과 사이드바 설명을 덜어내고 제목과 동작 버튼을 분리했다. 기준 글자 크기 22sp를 유지하면서 화면 폭과 글자 배율에 따라 한 열로 전환한다. 음성·언어 창의 닫기를 고정하고 배송 설명·오류 안내의 줄 수 제한과 강제 줄바꿈을 없앴다. 요청 접수·적용 확인·미지원·차단·미확인의 구분은 유지했다.

## 대표 변경

| 대상 | 변경 전 | 변경 후 |
|---|---|---|
| 영문 장식 | `FIND YOUR NEXT ESCAPE` 등 반복 표제 | 장식 표제 삭제 |
| 사이드바 | ‘찾기’ 아래 ‘나에게 맞는 캠핑장’ | 메뉴 이름만 표시 |
| 한국어 앱 이름 | 상단·하단 영문 표기 | ‘캠프룸’으로 표시 |
| 공간 설정 버튼 | 이 공간 설정 적용하기 | 설정 적용 |
| 배송 조건 확인 버튼 | 배송 가능 여부 확인 | 배송 조건 확인 |
| 음성 입력 필드 | 인식 결과 · 직접 입력 | 명령 입력 |
| 재고 없는 상품 | 비활성 버튼만 표시 | ‘품절’ 사유 표시 |
| 관리자 제공사 구분 | `Vehicle / Navigation / Commerce` | 차량 · 길안내 · 주문 |
| 관리자 데이터 상태 | ‘데모 데이터’와 `demo` 중복 | 같은 상태는 한 번만 표시 |
| 내 캠핑 그림 영역 | 영역 밖 그림과 아이콘의 겹침 | Canvas에 `clipToBounds` 적용 |

서버 업무 오류 31개를 새 번역 리소스 25개와 기존 리소스에 연결했다. 날짜·재고·배송 조건 등의 원인은 선택한 언어로 안내하고 알려진 업무 오류에 해당하지 않는 응답과 기술 예외는 일반 오류로 표시한다.

## 검증 범위

영상과 화면 검수의 APK를 최신 배포 APK와 구분한다.

| 근거 | 대상 소스 | 확인 범위 |
|---|---|---|
| 최신 Demo·Pleos APK | `49c7fe6` | 세 번째 빌드와 앱 단위 테스트 |
| 좁은 화면·기존 가로 화면 | `3edc322` | 한국어 좁은 화면 8장, 1280×800 영어·한국어·다크 화면 |
| 전체 흐름 녹화 | APK `3edc322` (`Camp_Room_Recorded_Demo.apk`) / 스크립트 `33c583a` | 앱 실행 체크 18개와 후속 진단 로그 검사 |

- **빌드·단위 검사:** 최신 Demo·Pleos 빌드에 성공했다. 앱 단위 테스트 14개에서 실패·오류·건너뜀은 각각 0개다. 영어·한국어 리소스는 각각 문자열 431개와 plurals 2개이며 키가 일치하고 강제 줄바꿈은 0개다.
- **네이티브 화면:** `3edc322` APK의 640×800·글자 배율 1.3·한국어 캡처 8장을 독립 검수했다. 찾기, 내 캠핑, 이동 준비, 차박 상단, 설정 버튼, 음성, 키보드 표시, 장바구니의 보이는 영역을 확인했다. 1280×800 영어·한국어·다크 화면도 확인했다.
- **최신 APK 추가 확인:** `49c7fe6` APK의 설치와 해시 일치를 확인했다. 내 캠핑과 하단 앱 이름 재캡처는 모두 같은 ‘응답 없음’ 창에 가려 정상 프레임을 얻지 못했다. 추가 두 수정은 소스·빌드 확인까지 완료했으며 정상 UI 실행 확인은 미완료다.
- **관리자 웹:** 최종 타입 검사를 통과했다. 로그인·운영 현황·캠핑장 관리·주문 관리를 1440px·768px·390px에서 검수한 12개 화면에 가로 넘침이나 한국어 단어 중간 분리가 없었다. 제공사 구분과 `demo` 중복 표시는 수정 후 다시 확인했다.
- **영상 실행:** 필터, 일정 저장, 길안내, 구역별 설정, 미리보기 비적용, 장바구니, 배송지 선택, 주문 한 건 저장, 장바구니 비움, 프로세스 재생성까지 진행해 앱 실행 체크 18개를 통과했다. 이후 `events.previous.jsonl`의 손상 행 1개로 진단 로그 검사가 중단돼 **자동 시나리오 전체 결과는 failed**다.
- **영상 내보내기:** 녹화는 한 번이며 재촬영하지 않았다. 보존한 680.836초 원본 WEBM·SRT를 3배속·마지막 3초 유지 조건으로 내보냈다. 최종 영상은 H.264·1920×1080·3분 49.93초, 3,621,010바이트다. 내보내기 성공을 앱 체크에 추가하지 않았다.

빌드·단위 검사 근거는 검수 작업 폴더의 `release/native-build.json`과 `release/static-checks.json`이다. 화면 근거는 `native-visual-review-part1~3.json`, 관리자 `admin-screens/review.json`과 캡처다. 진단 로그의 미통과 원인은 `artifacts/ui-copy-20261025/qa/telemetry-parser-failure.json`, 응답 없음 현상은 같은 검수 경로의 `final-ui/anr-observation.json`에 보존했다.

## 한계

- 좁은 화면 판정은 캡처에서 온전히 보이는 부분에 한정한다. 키보드를 연 상태의 하단 미리보기 접근성, 한국어 키보드 입력, 화면 밖의 긴 오류와 모든 동적 상태는 확인하지 못했다.
- 최신 APK 재확인 중 Android의 ‘응답 없음’ 대화상자가 한 번 관찰돼 안정성 통과로 판정하지 않았다. 원인은 미확정이며 기다리기를 한 번 선택한 기록을 보존했다.
- 최신 APK와 녹화 APK의 소스가 다르다. 최신 수정은 위 추가 확인 범위로 판단하며 이전 APK의 영상으로 최신 APK 전체 흐름을 통과 처리하지 않는다.
- 진단 로그 손상 행에는 선두 NUL이 포함돼 있다. 앱을 멈춘 뒤에도 손상이 남았고 원인은 미확정이다. 앱 크래시를 의도적으로 일으키는 추가 검증은 완료하지 못했으며 관측 기록 전체도 통과하지 못했다.
- 관리자 주문 화면은 캠핑장 6곳·주문 0건인 격리된 SQLite 데이터로 검수했다. 주문 상세와 저장 동작, 외부 제공사의 실제 장애 및 모든 상태 전환은 이번 화면 검수에 포함하지 않았다.
